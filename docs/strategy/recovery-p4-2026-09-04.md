## P4 technical changes

### 1. Release fingerprint

All routed HTML, 301 and 410 responses now expose:

`X-Werab-Release: recovery-p4-2026-09-04`

Purpose: post-deploy auditing can prove which source release actually served the request and detect stale instances/caches.

### 2. Sitemap policy

Expected sitemap inventory:

- INDEX: **86**
- Redirect: excluded
- GONE: excluded
- HOLD_NOINDEX: excluded
- DRAFT: excluded
- Canonical requirement: self canonical
- HTTP requirement: 200

`<priority>` is no longer emitted. Google documents that it ignores `<priority>` and `<changefreq>` values.

`<lastmod>` is emitted only when a verified date exists in content frontmatter or the manifest records a significant update. P3/P1 materially changed pages are dated `2026-09-04` where verified.

Google guidance: https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap

Expected inventory: `reports/seo/p4-expected-sitemap.csv`

### 3. Robots policy

`robots.txt` remains crawl-open and declares the absolute sitemap URL at the site root.

Expected production declaration:

`Sitemap: https://xn--c3c3a0aa6cvaf8b9dze.com/sitemap.xml`

### 4. Live production audit

Run after deployment:

`npm run audit:p4:live`

This checks:

- robots.txt
- sitemap status and exact 86-URL inventory
- absence of priority/changefreq
- P4 release header
- HTTP 200 for critical INDEX URLs
- self canonical
- no noindex on critical INDEX URLs

Run the full release gate before GSC submission:

`npm run audit:p4:live:full`

Full mode additionally checks:

- all 86 INDEX URLs
- all 53 one-hop 301 redirects and expected targets
- all 206 GONE URLs return 410
- release fingerprint on HTML/redirect/gone responses

Production GO requires this full audit to exit 0.
